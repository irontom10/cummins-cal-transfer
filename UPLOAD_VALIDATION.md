# Upload validation notes

## File-level CRC

`clip_cal_verify_ccal_crc()` requires all of:

```c
cummins_check_cal_file_crc(filename)
cummins_check_header_file_crc(filename)
cummins_check_file_crc(filename)
```

The check is performed at the top of `rp1210_upload_ccal()` before the RP1210
API is loaded, and again inside `clip_cal_send_ccal()` as a second barrier.

Known-good CCAL result:

```text
CheckCalFileCRC = True
CheckHeaderFileCRC = True
CheckFileCRC = True
```

Corrupting the first four CRC characters produced:

```text
clip_cal_send_ccal rc = -29 (CLIP_CAL_ERR_CRC)
send callback count = 0
```

## Raw programming stream

The final `clip_cal_send_ccal()` output was compared request-for-request with
the supplied Calterm recording from the first raw `02` through the final `07`.

```text
Calterm requests:   2287
Generated requests: 2287
Calterm bytes:      3664593
Generated bytes:    3664593
Mismatches:         0
```

This includes the short `0x00A00000` region, every 0x0640-byte bulk block,
short final blocks, region CRC-16/KERMIT values, final `0x2B16` write, and end
command.

## Loader transition

The Calterm recording transitions from authenticated CLIP with:

```text
12 20 00 0B
12 21 00 17 00
```

The ECM then closes CLIP.  Calterm later sends a session-specific initiator
close and begins raw-loader identification.  The current implementation does
not fabricate the unknown five session-dependent bytes of that close packet;
it uses the ECM close plus the captured loader-start delay and idempotent raw
identification probes instead.

## Completion timing

The first raw `02` request receives its interim `0E` immediately but its final
`0C 02` completion takes about 21.96 seconds in the recording.  The programming
completion timeout is therefore 60 seconds; a 5-10 second timeout would falsely
abort a valid Calterm-like transfer.
