# Calibration Transfer v0.5.0

Changes since [v0.1.0](https://github.com/irontom10/cummins-cal-transfer/releases/tag/v0.1.0).

## Highlights

- **Android support.** Added an Android application sharing the native ISO C89 calibration/J1939 core with the Windows x86 application. The Android transport uses the official NEXIQ mobile RP1210 SDK; vendor binaries are staged at build time and are not committed to the repository. Added Bluetooth adapter handling, larger selectors, responsive action buttons, and a build/diagnostic information dialog.
- **Broader ECM calibration readback.** Added ECH/ECHO-series readback and legacy ENI / ELITE II (CM550/CM554) download support alongside CLIP-family sessions, with protocol-family detection and separate transfer implementations. **ECH/ECHO, ECHO II, ENI, and ELITE II programming is intentionally blocked** pending matching programming validation.
- **Portable transport architecture.** Refactored the protocol implementation into a shared C89 core, a separate J1939 transport layer, and platform-specific RP1210 backends. Removed Win32-specific dependencies from shared protocol code, and improved RP1210 receive-frame handling on Android.
- **Shared settings.** Introduced a portable TOML configuration store for Windows and Android, preserving unknown keys and comments; added support for RP1210 automatic J1939 bitrate selection (`baud = 0`).
- **Safer calibration handling.** Strengthened calibration validation before upload, added platform-neutral descriptor diagnostics, and maintained pre-transfer CRC checks. The CLIP programming stream was validated request-for-request against a known-good trace (2,287/2,287 requests, 3,664,593 bytes, zero mismatches).
- **Width-tagged memory descriptors.** Fixed a live-ECM CLIP download regression by decoding range count and address/auxiliary/length element widths independently. Added 3-, 4-, and 5-range regression vectors, non-overflow/bounds checks, and preservation of opaque auxiliary fields and optional trailers. An independent INCAL scan detected 37,378 parseable descriptors, all accepted by the updated parser; 37,256 had exact HEX-region matches (99.67% of detected descriptors).
- **Build and test improvements.** Added native C89 protocol regression tests, automatic Windows/Android CI builds, release artifacts with SHA-256 files, and `builds/latest` publishing. Updated the Android build to retrieve the official mobile SDK during builds and improved CI retry handling.

## Important limitations

- **Calibration readback does not imply programming compatibility.** A valid `.ccal` file does not establish that it can safely be programmed into a particular ECM. ECH/ECHO and legacy-family uploads remain disabled.
- Android release APKs currently use the repository's development/debug signing configuration. Consult the project README for installation and supported adapter requirements.
- ECM uploads can be destructive. Use stable vehicle/ECM power, a reliable RP1210 connection, and a calibration confirmed for the target controller.

## Downloads

This release workflow builds a **Windows x86** executable and an **Android** APK, each with a SHA-256 checksum file. Release assets are attached after both platform builds complete successfully.
