# Upload validation

## File-level CRC gate

`clip_cal_verify_ccal_crc()` requires all supported file checks to pass:

```c
ccal_check_cal_file_crc(filename)
ccal_check_header_file_crc(filename)
ccal_check_file_crc(filename)
```

The check is performed at the top of `rp1210_upload_ccal()` before the RP1210 API is loaded, and again inside `clip_cal_send_ccal()` as a second barrier.

Known-good result:

```text
CheckCalFileCRC = True
CheckHeaderFileCRC = True
CheckFileCRC = True
```

A deliberately corrupted CRC produced:

```text
clip_cal_send_ccal rc = -29 (CLIP_CAL_ERR_CRC)
send callback count = 0
```

## Raw programming stream

The final `clip_cal_send_ccal()` output was compared request-for-request with a known-good reference trace from the initial transfer command through the final completion command.

```text
Reference requests: 2287
Generated requests: 2287
Reference bytes:    3664593
Generated bytes:    3664593
Mismatches:         0
```

That comparison includes the short metadata region, every full-size bulk block, short final blocks, region CRC-16/KERMIT values, the final parameter write, and the end command.

## Loader transition

The reference trace transitions from the authenticated application session with:

```text
12 20 00 0B
12 21 00 17 00
```

The controller then closes the application session and starts the raw loader.

The implementation deliberately does **not** fabricate unknown session-dependent close bytes. It uses the controller close, the observed loader-start delay, and idempotent identification probes instead.

This handoff remains the primary live-test boundary.

## Completion timing

The initial raw transfer request receives an interim response immediately, while final completion can take roughly 22 seconds.

The programming completion timeout is therefore 60 seconds; a short timeout can falsely abort a valid transfer.
