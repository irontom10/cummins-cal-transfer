# Cummins CAL Transfer

Windows x86 tool for downloading and uploading Cummins ECM calibration data over **CLIP / J1939 / RP1210**.

The project is split into a small WinForms front end and a C89 native core. The native DLL is built first, embedded into the managed executable, and extracted to a versioned per-user cache at runtime.

## What it does

- **Download CAL** from an ECM and write a Calterm-style `.ccal`.
- **Upload CCAL** after validating the native Cummins file CRCs.
- Discover installed RP1210 APIs/devices.
- Perform the recovered CLIP session authentication and calibration transfer flow.
- Provide a standalone CRC checker/setter for calibration files.

## Current validation status

The raw calibration-loader stream generated by this implementation was compared request-for-request against the supplied Calterm capture:

- 2,287 requests generated
- 3,664,593 bytes generated
- 2,287 / 2,287 requests matched
- zero byte mismatches

Upload is gated by all three recovered Cummins file checks:

```text
CheckCalFileCRC
CheckHeaderFileCRC
CheckFileCRC
```

A bad file is rejected before the RP1210 adapter is opened.

The remaining live-test boundary is the CLIP-to-loader shutdown timing around the session-specific initiator close. The code does not replay stale captured session bytes. See [docs/upload-validation.md](docs/upload-validation.md) for the capture-matched details and that boundary.

## Build

### Requirements

- Windows
- Visual Studio C++ x86 build tools
- .NET 10 SDK
- A 32-bit RP1210 implementation for the adapter you intend to use

From a Visual Studio Developer Command Prompt/PowerShell, or a normal shell with Visual Studio installed:

```bat
build_x86.bat
```

The script will locate the Visual Studio x86 toolchain when necessary, build the native core, then run `dotnet publish`.

### Outputs

```text
build\publish\CumminsCalTransfer.exe
build\crc_call.exe
```

`rp1210scan.dll` is embedded in `CumminsCalTransfer.exe`; it is not required beside the executable.

No Cummins `CRCUtility.dll` is required. The recovered CRC implementation is compiled directly into the native core and the standalone CRC utility.

## CRC utility

Check a calibration file:

```bat
build\crc_call.exe check mycal.ccal
```

Set the recovered file CRC fields:

```bat
build\crc_call.exe set mycal.ccal
```

## Architecture

```text
Program.cs
   |
   | P/Invoke
   v
rp1210scan.dll
   |
   +-- RP1210 discovery / vendor API loading
   +-- J1939 transport
   +-- CLIP session + authentication
   +-- calibration download/upload
   +-- Cummins file CRC handling
```

## Source layout

| File | Purpose |
| --- | --- |
| `Program.cs` | WinForms UI and native DLL loader |
| `rp1210scan.c/.h` | RP1210 API/device discovery |
| `rp1210clip.c/.h` | RP1210 transport, CLIP state, download/programming flow |
| `clip_crypto.c/.h` | Recovered CLIP seed/context cryptography |
| `clip_cal.c/.h` | Calibration readback helpers and raw CCAL programming protocol |
| `cummins_crc.c/.h` | Native Cummins calibration-file CRC implementation |
| `crc_call.c` | Standalone CRC CLI |
| `rp1210scan.def` | Stable exports used by P/Invoke |
| `caltool.csproj` | .NET 10 WinForms single-file publish configuration |
| `build_x86.bat` | Reproducible x86 native + managed build |

## Programming caution

ECM programming is not a read-only operation. Use stable vehicle power, a reliable RP1210 connection, and a calibration intended for the target module. Do not interrupt power or communications during an upload.
